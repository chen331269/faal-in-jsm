# 把 FAAL 防抖滤波器接进 JoyShockMapper：一次实践记录

这不是一个 JSM 的发行版，也不是一个 fork。它是一份**工程记录**：
记录把 [FAAL Filter](https://github.com/chen331269/FAAL-Filter) 接进陀螺仪瞄准的两条输出路径时，
遇到的问题、推导出的性质、以及用真实手柄数据验证的结果。

代码以 **patch** 形式提供，可应用到 [hotuns/JoyShockMapper](https://github.com/hotuns/JoyShockMapper)
（JSM Studio 使用的子模块）的 `jsm-studio` 分支。完整源码不在本仓库。

---

## 1. FAAL 是什么，为什么接起来不简单

FAAL 是一个帧率无关的自适应滤波：用 One Euro 做平滑、用峰值跟踪做减速率抑制、
用抑制状态机做自适应释放。它的设计前提是**二维意图**——横向甩枪和纵向抖动必须分开处理。

在 JSM 里把它接上，难度不取决于滤波器本身，而取决于**它站在哪**：

```
A 鼠标模式：陀螺仪 → 标定 → 空间转换 → FAAL → 灵敏度/曲线 → 鼠标
B PS_MOTION：陀螺仪 → 标定 → [玩家空间映射 → FAAL → 折回3D] → 虚拟手柄 → 游戏内部转换 → 瞄准
```

**A 站在空间转换之后**，拿到的已经是"横向/纵向"两个意图量，直接二维滤波即可。

**B 站在之前**——因为游戏自己做转换，外部软件只能原样转发陀螺仪。
在三维角速度上做各向异性（分轴）抑制会扭曲旋转向量本身。

这就是全部问题的来源。

---

## 2. 关键性质：齐次性

一开始想的是"复刻游戏内部的空间转换"，那会掉进姿态漂移和反投影的坑里。
后来意识到不需要：

```text
T(s · V) = s · T(V)
```

游戏的空间转换对陀螺仪向量是齐次的。而乘法在齐次映射下可交换——所以在**同一个基**上做乘法，
就会原样传递到游戏的二维输出。**只需要对齐"基"，不需要复刻"算法"。**

实测（真实录制，逐帧比对）：对原始向量按 0.5 / 0.3 分轴缩放，重算玩家空间输出的相对误差
**0.00e+00**；在真实转发路径上（含浮点与记录精度）残差 ≤ 0.02。

## 3. 实现

用**玩家空间**（player space）：yaw 由重力定参考，pitch 保持手柄本地轴。

```cpp
// 映射（与 JSM 的 PLAYER_TURN 一致）
yaw   = sign(G·(0,Y,Z)) · min(|G·(0,Y,Z)| · 2, |(Y,Z)|)
pitch = -X

// 对这两个标量跑 FAAL，得到 s_yaw / s_pitch

// 折回三维
X *= s_pitch;
Y *= s_yaw;
Z *= s_yaw;      // roll 与 yaw 共用水平面通道
```

没有除法、没有求逆、没有奇点。加速度原样转发，游戏的重力估计不受影响。

## 4. 数据

### 4.1 选择性（鼠标模式）

| 场景 | 行程保留 | 被抑制 |
|---|---|---|
| 慢速跟靶 | 95.7% | 4.3% |
| 反复甩枪 | 85.6% | 14.4% |
| 抖动 + 画圈 | 57.9% | 42.1% |

同一速度档（5–20 deg/s）：跟靶压 4.6%、抖动压 51.5%——**差 11 倍**。
它区分的不是"动得多快"，而是"方向反复得多厉害"。

甩枪内部抑制是**反速度**的：100–300 deg/s 只压 8.5%，1–20 deg/s 压 38–47%。
甩枪主体原样通过，被压的是起步与收尾的慢速段——手抖、过冲、微调所在的地方。

### 4.2 PS_MOTION（含直通对照组）

| | OFF（直通） | ON（预处理） |
|---|---|---|
| 二维行程保留 | 99.9% | **84.7%** |
| s_yaw / s_pitch 中位 | 1.00 / 1.00 | 0.95 / 0.84 |
| 三维方向偏折 p50 | 0.00° | **1.42°** |
| 齐次性残差 | 6.5e-04 | 1.9e-02 |

OFF 段证明测量链路本身不引入误差；ON 段证明压制是真的、且方向基本没动。

## 5. 踩过的坑

**① 记录必须先想清楚。** 最初只记了滤波前的输入，所有抑制率都是"离线重放"推导的——
依赖"参数没变"和"初始状态一致"两个未验证的前提。后来补记了**实际输出**，数字才变成实测。

**② 参数存在"悬崖"。** `SIGN_CHANGE_THR` 在 5~10 之间从"全砍"跳到"完全不砍"，
1.5 以下会在普通快速跟踪中误触发。调参必须在真实数据上做，靠猜会踩到边界。

**③ 垂直轴的特殊性。** pitch 是手柄本地轴，没有互补滤波兜底，所以**输入信号本身**比水平更吃手抖。

但抑制本身是生效的，而且和水平一样完整——这里容易搞混：
重力校正作用在**姿态估计**上，不作用在**瞄准量**上。主流游戏把角速度直接积分成镜头角度，
校正不参与这条路径；只有"用被校正的姿态反推瞄准量"的实现，pitch 的抑制才会被部分补偿。
实测（Call of Duty: Modern Warfare III（2023））从表现看属于前者。观感上的"垂直偏钝"来自抑制量更大
（见 4.2 的 0.84 vs 0.95），不是被撤销。

**④ 线程。** FAAL 跑在 1 kHz 的输入线程，而改参数发生在命令线程。
重置、记录、参数读取都要考虑这一点，否则是"几十次启动崩一次"。

## 6. FakerInput 是什么

代码改动落在这条路径上，所以单独说明。**FakerInput** 是 Windows 的虚拟 HID 驱动 + 用户态 DLL
（上游：Ryochan7/FakerInput）。它注册一个虚拟键盘/鼠标设备，应用通过 `FakerInputDll.dll`
把事件写进去，系统当作真实硬件处理。

JSM 用它而不是 `SendInput`，是因为注入层级不同：

| 方式 | 层级 | 游戏能分辨 |
|---|---|---|
| `SendInput` | 用户态 API | 部分反作弊可以识别为合成事件 |
| `FakerInput` | 内核态虚拟 HID | 对游戏而言与物理设备无差别 |

运行时需要：装驱动（管理员）、`FakerInputDll.dll` 放在可执行文件旁、加载失败会回退到系统输入。
**这属于内核级输入注入，部分反作弊会视为可疑行为，风险自负。**

## 7. 直接跑一遍

`dist/` 里是编译好的可执行文件（Windows x64 Release），对应本仓库的 patch：

| 文件 | 说明 |
|---|---|
| `JoyShockMapper.exe` | 主程序（含 FAAL 与 PS_MOTION 预处理） |
| `SDL3.dll` | 手柄输入后端 |
| `FakerInputDll.dll` | 虚拟输入后端 |

**前提**：FakerInput **驱动**需要单独安装（管理员权限，会创建虚拟 HID 设备）；
本仓库只带用户态 DLL。二进制未签名，首次运行会被 SmartScreen 拦截。

跑起来之后：

```
FAAL_PSMOTION        # 切换预处理开关，A/B 对比手感
FAAL_TRACE_START     # 开始记录
FAAL_TRACE_STOP      # 停止并写出 faal_trace.csv
```

> **不想直接运行二进制？** 可以自己编译验证：见 [`BUILD.md`](BUILD.md) 的完整步骤
> （克隆 `jsm-studio` 分支 → `git apply patch/changes.diff` → CMake 构建），
> 下载到的文件也可以用 [`dist/SHA256SUMS`](dist/SHA256SUMS) 校验。
>
> 注意：本程序会创建虚拟手柄并通过 FakerInput 注入键鼠事件，**被部分杀软/反作弊误报属于预期**，
> 原因和验证方式写在 `BUILD.md` 第 5 节。

## 8. 工具与复现
记录每帧的：滤波前二维值、当帧生效的 4 个参数、**空间转换前的原始三维陀螺仪**、
**重力向量**、**四元数**、**实际输出的向量**。

```
FAAL_TRACE_START / FAAL_TRACE_STOP     # 记录与停止（15 万帧 ≈ 150 秒）
FAAL_PSMOTION                          # 预处理开关，A/B 盲测
```

`tools/` 里三个离线分析器：

| 工具 | 用途 |
|---|---|
| `faal_replay.cpp` | 消融、分速度档统计、参数 what-if、波形导出、输出指纹 |
| `space_check.cpp` | 识别录制用的陀螺仪空间、齐次性验证、握持转动统计 |
| `psmode_measure.cpp` | 直接从记录的输出列算实测增益与方向偏折 |

## 9. 边界

1. **只对玩家空间成立**——换成世界空间映射会破坏齐次性，折回三维会出现预料之外的旋转；
2. 世界空间游戏会偏折（二维方向差 p50 3.7° / p99 20.8°，串扰约 9%~18%）；
3. 抑制能否保持取决于轴与重力的关系（见 5-③）；
4. roll 与 yaw 共用水平面通道，没有独立增益；
5. 只适用于"游戏读物理陀螺仪"的场景，VR 走的是另一套驱动层。

# FAAL 的两条输出路径：鼠标模式 与 PS_MOTION

本文说明 FAAL 在 JSM 两种陀螺仪输出方式下所处的位置、各自的处理链、共用的部分，以及实测差异。

---

## 0. 一张图

```
                        ┌──────────────── 分支 A：鼠标模式 ────────────────┐
                        │                                                │
物理陀螺仪 ─► 标定 ─► 空间转换(WORLD/PLAYER/LOCAL) ─► FAAL ─► 灵敏度/曲线 ─► 鼠标
                        │      (gyroX, gyroY 已含"玩家意图")              │
                        └────────────────────────────────────────────────┘

                        ┌──────────────── 分支 B：PS_MOTION ─────────────┐
                        │                                                │
物理陀螺仪 ─► 标定 ─► [玩家空间映射 ─► FAAL ─► 折回三维] ─► 虚拟手柄 ─► 游戏内部空间转换 ─► 瞄准
                        │        (我们只能站在游戏转换之前)               │
                        └────────────────────────────────────────────────┘
```

关键差别：**A 在空间转换之后，B 在之前。** A 拿到的已经是二维意图；B 拿到的是三个正交角速度，
必须自己先构造出"意图"再过滤。

## 1. 共用部分

| 项 | 说明 |
|---|---|
| 滤波内核 | `faal_filter.cpp`，两条路径共用同一份代码与同一组参数 |
| 参数 | 12 个 `FAAL_*` 设置，逐帧读取，支持和弦（如 `ZL,FAAL_SIGN_CHANGE_THR = 0`） |
| 运行时改参 | 下一帧生效；不重置滤波器状态 |
| 状态 | 全局静态（峰值、抑制水位、冻结计时、One Euro 状态）；同一时刻只有一条路径在跑 |
| 逐帧记录 | 两条路径都记录，但 `out_*` 的语义不同（见 §4） |

## 2. 分支 A：鼠标模式

**位置**：`main.cpp`，`if (!isDirectOutput)` 分支。

**输入**：`gyroX / gyroY` —— 已经过空间转换（`GYRO_SPACE` = LOCAL / PLAYER_TURN / PLAYER_LEAN /
WORLD_TURN / WORLD_LEAN），是玩家视角下的"横向 / 纵向"。

**处理**：

```cpp
const float inX = gyroX, inY = gyroY;
faal_filter(gyroX, gyroY, deltaTime);        // 2D 版本
traceInput(inX, inY, 0.f, gyroX, gyroY, 0.f);
```

**输出**：滤波后的二维值，随后经过灵敏度、加速曲线、陀螺仪平滑等，最终成为鼠标位移。

**实测（三段真实操作，重放推导）**：

| 场景 | 行程保留 | 被抑制 |
|---|---|---|
| 慢速跟靶 | 95.7% | 4.3% |
| 反复甩枪 | 85.6% | 14.4% |
| 抖动 + 画圈 | 57.9% | 42.1% |

同一速度档（5–20 deg/s）：跟靶压 4.6%、抖动压 51.5%，**差 11 倍**——它区分的不是速度，
而是方向反复的剧烈程度。

甩枪内部抑制是**反速度**的：100–300 deg/s 只压 8.5%，1–20 deg/s 压 38–47%。
甩枪主体原样通过，被压的是起步与收尾的慢速段（手抖、过冲、微调）。

## 3. 分支 B：PS_MOTION

**位置**：`main.cpp`，`if (isDirectOutput)` 分支。

**输入**：`inGyroX/Y/Z` —— **标定之后、空间转换之前**的原始三维角速度。
（改动前这里转发的是未标定的 `imu.gyro*`，属于既有缺陷，已修。）

**为什么不能直接分轴滤波**：三个分量是物理轴的，直接各向异性缩放会扭曲角速度向量的方向。
所以要先把它投影到"玩家意图"空间。

**处理三步**：

```cpp
// 1. 玩家空间映射（与 PLAYER_TURN 一致）
faalPlayerSpace2D(inGyroX, inGyroY, inGyroZ, inGravX, inGravY, inGravZ, psYaw, psPitch);
//    yaw   = sign(G·(0,Y,Z)) · min(|G·(0,Y,Z)|·2, |(Y,Z)|)     ← 重力参考，60° 缓冲
//    pitch = -X                                                 ← 手柄本地轴

// 2. 在这两个标量上跑 FAAL
faal_filter(psYaw, psPitch, deltaTime);

// 3. 取比例折回三维
float sYaw   = psYaw   / origYaw;
float sPitch = psPitch / origPitch;
directGyroX = inGyroX * sPitch;   // 俯仰轴
directGyroY = inGyroY * sYaw;     // 这两轴共同构成 yaw
directGyroZ = inGyroZ * sYaw;
```

**为什么这样可以**：映射对 `(Y,Z)` 和 `X` 都是**齐次**的（输入乘 s，输出乘 s），
所以在上游乘一个标量，游戏内部的二维输出会精确乘同一个标量。不需要复刻游戏的算法，
只需要基一致。实测齐次性残差 0.019（几十 deg/s 量级上的绝对误差）。

**开关**：`FAAL_PSMOTION` 在"预处理"与"标定后直通"之间切换，用于 A/B 盲测。

**实测**：

| | OFF（直通） | ON（预处理） |
|---|---|---|
| 会话 | 40.4 s | 53.2 s |
| 二维行程保留 | 99.9% | **84.7%** |
| s_yaw 中位 | 1.00 | 0.95 |
| s_pitch 中位 | 1.00 | 0.84 |
| 三维方向偏折 p50 | 0.00° | **1.42°** |
| 偏折 p90 / p99 | 0.03° / 0.03° | 33.6° / 51.5° |

OFF 段作为对照组，证明测量链路本身不引入误差。

## 4. 记录在两条分支上的差异

同一份 CSV 格式，但 `out_*` 的语义不同：

| 列 | 分支 A | 分支 B |
|---|---|---|
| `gx, gy` | 空间转换后的二维 | 玩家空间映射结果（滤波前） |
| `gz` | 恒为 0 | 恒为 0 |
| `raw_*` | 标定后的原始三维 | 同左 |
| `grav_*`, `quat_*` | 同一帧的参考系 | 同左 |
| **`out_*`** | **滤波后的 `(yaw, pitch, 0)`**，交给灵敏度 | **转发给虚拟手柄的三维向量** |

这也是 `psmode_measure` 能直接算实测增益、而普通回放只能推导的原因。

## 5. 共同的收益与共同的边界

**收益**：抑制由"方向反复"驱动，不由速度驱动——慢速跟靶几乎不受影响，抖动被压四成以上。

**边界**：

1. **本实现只对玩家空间成立。** 换成世界空间映射时，俯仰和偏航都由重力平面重新投影，
   映射不再是齐次的常系数关系，折回三维会出现预料之外的旋转。不要用世界空间映射来"适配"世界空间游戏。
2. **世界空间游戏会偏折**：若游戏内部按重力投影定义 yaw，与我们按玩家空间压制，
   两者对同一段动作的二维方向差 p50 3.7° / p99 20.8°，串扰约 9%~18%。症状是慢速正常、快甩偏方向。
3. **抑制能否保持取决于轴与重力的关系**：绕重力轴的分量不受 accel 校正，抑制完整保留；
   垂直重力轴的分量会被互补滤波拉回，抑制部分撤销。所以 yaw 的抑制是实的，pitch 会被部分抵消。
4. **roll 与 yaw 共用水平面通道**：玩家空间的 yaw 由 `(Y, Z)` 合成，折回时同乘 `s_yaw`，
   没有独立的 roll 增益。若游戏单独使用 roll，`s_yaw` 也会作用于它。
5. **玩家空间的垂直轴没有互补滤波**，pitch 就是本地 X 轴，比水平更吃手抖——选择玩家空间的连锁反应。
6. **垂直抑制比水平重**（实测 0.84 vs 0.95），因为 pitch 速度通常只有 yaw 的三分之一，落在低速重抑制区。

# 玩家空间预滤波：把 FAAL 用在原生陀螺仪游戏上

> 适用于「游戏自己读物理陀螺仪、自己做空间转换」的场景（虚拟手柄 / PS_MOTION 转发）。
> 本文记录该方案的原理、实现、实测数据与已知边界。

---

## 1. 问题

FAAL 的抑制逻辑建立在**二维意图**上：横向甩枪和纵向抖动必须分别处理。
在映射成鼠标的用法里，FAAL 接在空间转换**之后**，天然拿到这两个轴。

但原生游戏自己完成空间转换，外部软件只能把陀螺仪**原样转发**。于是 FAAL 被迫站在转换的
**上游**，看到的是三个正交的物理角速度分量——那里没有"上下"和"左右"。

如果直接对这三分量做各向异性（分轴）抑制，等于在物理空间里扭曲角速度向量。

---

## 2. 关键性质：齐次性

不需要复刻游戏内部的算法。游戏的空间转换对陀螺仪向量是**齐次**的：

```text
T(s · V) = s · T(V)
```

而乘法在齐次映射下可交换。所以在**同一个基**上做乘法，就会原样传递到游戏的二维输出：

```text
T( diag(s_yaw, s_pitch, 1) · V ) = ( s_yaw · T_yaw(V),  s_pitch · T_pitch(V) )
```

**只需要对齐"基"，不需要复刻"算法"。** 四元数、反投影矩阵、姿态追踪，一样都不用。

实测验证（真实手柄录制，逐帧比对）：

```
对真实数据把 (Y,Z) 乘 0.5、X 乘 0.3，重算玩家空间映射
  max relative error  yaw 0.00e+00   pitch 0.00e+00
```

---

## 3. 实现

采用 **玩家空间（player space）**：yaw 由重力定参考，pitch 保持手柄本地轴。

```
w      = normalize(gravity)
ny, nz = w.y, w.z

yaw    = sign(w·(0, gy, gz)) · min(|w·(0, gy, gz)| · 2, |(gy, gz)|)   // 60° 缓冲
pitch  = -gx
```

对这两个标量分别跑 FAAL，得到滤波后的值，再取比例折回三维：

```
s_yaw   = yaw_filtered   / yaw_raw
s_pitch = pitch_filtered / pitch_raw
```

```
V' = ( X * s_pitch,  Y * s_yaw,  Z * s_yaw )
```

两个方向的映射都是齐次的，所以上式是**精确**的，不是近似：
缩放 `(Y,Z)` 会让游戏收到的 yaw 精确缩放 `s_yaw`，缩放 `X` 会让 pitch 精确缩放 `s_pitch`。

**不加除法、不求逆、无奇点。** 加速度原样转发，游戏的重力估计不受影响。

## 4. 实测

> **数据来源说明。** 4.1–4.2 的数字由「记录滤波前的输入 → 离线用同一份滤波器代码重放」得到，
> 依赖两个前提：会话期间未被记录的参数没有变化；重放的初始状态与实机一致。
> 4.3 的数字是**实测的**——记录里带了 `out_x/out_y/out_z`（真正送出去的向量），
> 直接 `out/in` 即可，不经过重放。

### 4.1 选择性（鼠标模式，三段真实操作）

| 场景 | 行程保留 | 被抑制 |
|---|---|---|
| 慢速跟靶 | 95.7% | 4.3% |
| 反复甩枪 | 85.6% | 14.4% |
| 抖动 + 画圈 | 57.9% | 42.1% |

同一速度档下的对比最能说明问题：

| 角速度 | 跟靶时抑制 | 抖动时抑制 |
|---|---|---|
| 5–20 deg/s | **4.6%** | **51.5%** |

差 11 倍——FAAL 区分的不是"动得多快"，而是"方向反复得多厉害"。

### 4.2 甩枪内部的抑制是反速度的

| 角速度 | 平均抑制 |
|---|---|
| 1–5 | 46.8% |
| 5–20 | 38.3% |
| 20–50 | 27.9% |
| 50–100 | 14.5% |
| **100–300** | **8.5%** |

甩枪的主体几乎原样通过，被压的是起步和收尾的慢速段——手抖、过冲、微调所在的地方。

### 4.3 原生游戏转发（PS_MOTION）

**以下为实测值**：直接由记录中的 `out`（真正转发给虚拟手柄的向量）与 `raw` 相除得到，
不经过任何重放。

| 指标 | OFF（直通） | **ON（预处理）** |
|---|---|---|
| 会话长度 | 40.4 s | 53.2 s |
| s_yaw 中位 | 1.00 | **0.95** |
| s_pitch 中位 | 1.00 | **0.84** |
| 二维行程保留 | 99.9% | **84.7%** |
| 三维方向偏折 p50 | 0.00° | **1.42°** |
| 偏折 p90 / p99 | 0.03° / 0.03° | 33.6° / 51.5° |
| 齐次性残差（max） | 6.5e-04 | 1.9e-02 |

OFF 段是干净的直通基线：`s = 1.00`、方向零偏折、行程 99.9%，证明测量链路本身没有引入误差。

ON 段：中位偏折 **1.42°**，因为大多数帧两轴压制接近；大的偏折只出现在
"被压得狠的那根轴恰好主导该帧运动"时，这是各向异性的定义本身，对二维输出无影响。
齐次性残差 0.02 以内，说明"缩放 `(Y,Z)` 会等比传递到游戏的 yaw"在**真实转发路径上**成立。

## 5. 已知边界

**① 本实现只对玩家空间成立。** 整条链路（映射 → 抑制 → 折回）建立在"pitch 是本地 X 轴、
yaw 是 Y/Z 的水平合成"这一前提上。换成世界空间（`WORLD_TURN` / `WORLD_LEAN`）时，
俯仰和偏航都由重力平面重新投影，映射不再是齐次的常系数关系，折回 3D 会出现预料之外的旋转——
所以**不要把 `faalPlayerSpace2D()` 换成世界空间的映射来"适配"世界空间游戏**。

**② 世界空间游戏会偏折。** 如果游戏内部按重力投影定义 yaw，而我们按玩家空间压制，
两者对同一段动作的定义差：

| | p50 | p90 | p99 |
|---|---|---|---|
| 二维运动方向夹角 | 3.7° | 10.9° | 20.8° |

串扰 ≈ `sin(θ) × 两轴增益差`，p90 约 9%，p99 约 18%。症状是**慢速正常、快甩时准星轻微偏方向**。

**③ 抑制能否保持，取决于旋转轴与重力的关系，而不是通道划分。**

| 旋转轴 | 改变重力方向 | accel 会校正 | 抑制 |
|---|---|---|---|
| 绕重力轴（水平转向） | 否 | 否 | **完整保留** |
| 垂直重力轴（俯仰） | 是 | 看游戏怎么用 | **通常也完整保留** |

这里要区分两件事：

- **重力校正作用在"姿态估计"上**，不是作用在"瞄准量"上。互补滤波修正的是陀螺积分出来的
  姿态与加速度计测到的重力之间的偏差。
- **瞄准是否会被补偿，取决于游戏怎么消费**：
  - 主流做法是**把角速度积分成镜头角度**（速率驱动）——校正不参与这条路径，
    所以 pitch 的抑制和 yaw 一样完整保留；
  - 只有当游戏**用被重力校正的姿态去推导瞄准量**（绝对指向类）时，pitch 的抑制才会被部分补偿。

实测（Call of Duty: Modern Warfare III（2023），PS_MOTION 转发）从表现看属于前者：
**pitch 的抑制确实生效**，观感上的"垂直偏钝"来自抑制量更大（见 ⑥），不是被撤销。

**④ roll 与 yaw 共用水平面通道。** 玩家空间的 yaw 由 `(Y, Z)` 共同构成，
折回时两者乘同一个 `s_yaw`，没有独立的 roll 增益。若游戏把 roll 单独使用
（渲染枪械倾斜、世界空间 roll 补偿），`s_yaw` 也会作用于它。

**⑤ 玩家空间的垂直轴没有互补滤波。** pitch 就是手柄本地 X 轴，重力完全不参与，
所以垂直方向会比水平更容易受手抖影响——这是选择玩家空间的连锁反应，无法在空间映射层解决。
实际观感比"完全不处理"好很多，但要清楚它存在。

**⑥ 垂直抑制比水平重。** 真实操作里 pitch 速度通常只有 yaw 的三分之一，
落在 FAAL 的低速重抑制区（实测 s_pitch 0.84 vs s_yaw 0.95），上下瞄准会比左右更"钝"。

## 6. 调参入口

| 症状 | 调什么 |
|---|---|
| 垂直发黏 | 降低低速段抑制强度：`SIGN_CHANGE_THR` 或 `PEAK_DECAY_TIME` |
| 甩枪收尾过多 | `HYST_FALL_TIME` / `FREEZE_DURATION_SEC` |
| 按住扳机时抖动放出 | 和弦覆盖：`ZL,SIGN_CHANGE_THR = 0` 会关掉过零通道 |
| 整体太钝 | `PEAK_MIN_TRIGGER`（内部固定，需改代码） |

参考：`SIGN_CHANGE_THR` 的"悬崖"在 5~10 之间，1.5 以下会在普通快速跟踪中误触发。

## 7. 复现方法

逐帧记录滤波器的输入、当帧参数、**空间转换前的原始三维陀螺仪、重力、四元数**，
事后用同一份滤波器代码离线重放：

```
FAAL_TRACE_START      # 开始（15 万帧容量，1000 Hz 下约 150 秒）
FAAL_TRACE_STOP       # 停止并写出 faal_trace.csv
```

离线工具可以给出：行程保留率、分速度档抑制率、逐通道消融、参数 what-if、
方向偏折分布、以及输出序列的位级指纹（用于证明改动前后行为一致）。
